# 批量读取维修任务

页面查询现在优先读取 PostgreSQL 完整设备缓存，缺失时通过以下 API 策略入库；同步按钮更新全量数据。配置和一致性规则见 [PostgreSQL 数据库与同步](postgresql.md)。

API 读取默认先调用 `GET /machines/{machineId}/export/incidents`，每台设备读取一批完整故障，再按设备、故障状态及维修任务 `createdAt` 筛选。北京时间起止日期包含全天。不会将维修任务日期传给故障接口，避免遗漏旧故障下新增的维修任务。

依据：[Festo 官方 OpenAPI](https://developers.festo.com/portals/api/sites/festo-se-prod-prodportal/liveportal/apis/digismartenance-premiumpublicprod/spec)，2026-10-29 读取，build 5.0.3。

## 数据转换

- 接口描述写的是 blob URI，但响应 schema 写的是故障对象。实现兼容 JSON 数组、单个完整故障、带完整数量信息的 `items` 包装，以及纯文本/JSON 字符串 URI 和 `uri`、`url`、`downloadUrl` 包装。
- 签名下载链接仅接受 HTTPS Azure Blob Storage，下载时不发送 API 令牌、Cookie，也不跟随重定向。
- 将 `machine.id`、创建人/修改人对象转换成现有 CSV 使用的字段。
- 原始自定义栏位缺少名称时，查询 `/customfields/incidents` 和 `/customfields/tasks`，按 ID 补齐标签和翻译。每次查询最多加载一次这两组定义，不跨账号缓存。
- 批量请求/下载超时为 120 秒，单个响应解码后最大 64 MiB。

## 回退与完整性

无批量权限（403）、接口不存在（404）、不支持的方法（405/501），或无法可靠解析的批量格式，自动使用现有列表分页及详情查询。整台设备的批量数据通过转换后才开始加入结果，避免回退时混入半份数据。未知自定义栏位名称、缺失维修任务集合、重复故障 ID、设备不匹配和不完整分页包装也不会被当作成功的批量结果。

401 会终止查询；429 仍遵循冷却与退避；连接错误继续使用原有有限重试。取消或最终失败时不提供部分结果。结果区显示原查询中使用批量与标准方式的设备数量，本地二次筛选保留该来源信息。

批量接口、文件下载或栏位定义接口返回 HTTP 500 时，立即回退标准查询；HTTP 502/503/504 在原有有限重试失败后也会回退。同次查询的后续设备直接使用标准查询，下一次查询重新尝试批量。标准查询本身失败仍会终止并丢弃部分结果。仅真实 HTTP 服务端错误触发此规则，不将重定向或本地校验错误混作 HTTP 502。

## 请求数与验证

原方式约需：1 次设备列表 + 各设备故障列表页数 + 需要检查的故障详情数。

批量成功时约需：1 次设备列表 + 每台设备 1 次批量请求 + 每台设备至多 1 次文件下载 + 必要时 2 次栏位定义查询。现有 500ms 请求间隔保留，提速来自减少请求数。

运行 `npm test`、`npm run typecheck`、`npm run lint`、`npm run build`。

自动测试使用依据官方 schema 构造的响应，覆盖 CSV 与标准接口一致性、日期边界、旧故障新增维修任务、字段映射、回退、取消及文件下载凭证隔离。尚未使用真实账号验证权限、实际 blob 包装或实际耗时；遇到未识别格式会显示标准查询计数。
